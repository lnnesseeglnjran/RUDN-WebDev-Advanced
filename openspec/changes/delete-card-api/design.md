## 1. Удаление карточки из массива

### Вариант 1: `findIndex` + `splice`

```ts
const index = cards.findIndex((c) => c.id === id);
if (index === -1) {
  res.status(404).json({ error: "Карточка не найдена" });
  return;
}
cards.splice(index, 1);
res.status(204).end();
```

**Плюсы:** одна проверка на существование и удаление на месте. `cards` объявлен через `const`, а `const` запрещает только переназначение переменной, содержимое массива менять можно.
**Минусы:** массив изменяется напрямую.

### Вариант 2: `filter` с пересозданием массива

```ts
const exists = cards.some((c) => c.id === id);
if (!exists) { /* 404 */ }
cards = cards.filter((c) => c.id !== id);
```

**Плюсы:** не изменяет исходный массив.
**Минусы:** нужен `let` вместо `const`, массив создаётся заново, а существование приходится проверять отдельным проходом.

### Выбор: `findIndex` + `splice`

Массив маленький и живёт в памяти, поэтому удаление на месте проще. Индекс нужен и для проверки 404, и для удаления, отдельный проход не нужен.

## 2. Обработчик неизвестных адресов

### Вариант 1: `app.use` без пути

```ts
app.use((req, res) => {
  res.status(404).json({ error: "Маршрут не найден" });
});
```

**Плюсы:** срабатывает для любого метода и пути, если ни один роут не ответил раньше. Не зависит от синтаксиса путей.
**Минусы:** по записи не сразу видно, что это запасной обработчик.

### Вариант 2: `app.all` со звёздочкой

```ts
app.all("/*splat", (req, res) => {
  res.status(404).json({ error: "Маршрут не найден" });
});
```

**Плюсы:** явно показывает «любой метод, любой путь».
**Минусы:** в Express 5 звёздочку нужно называть (`/*splat`), старая запись `"*"` выдаёт ошибку, поэтому код привязан к версии Express.

### Выбор: `app.use` без пути

Запись короче и не зависит от версии Express. Порядок в коде определяет приоритет: обработчик стоит после всех роутов и срабатывает, только если ни один роут не ответил.

## 3. Обработчик ошибок

### Вариант 1: четыре параметра `(err, req, res, next)`

```ts
app.use((err: Error, req: express.Request, res: express.Response, next: express.NextFunction) => {
  res.status(500).json({ error: "Внутренняя ошибка сервера" });
});
```

**Плюсы:** Express распознаёт обработчик ошибок именно по четырём параметрам и вызывает его для любой ошибки, брошенной в роутах и middleware.
**Минусы:** если убрать любой параметр, Express перестанет считать функцию обработчиком ошибок и тихо пропустит её.

### Вариант 2: `try/catch` в каждом роуте

**Плюсы:** ошибки обрабатываются рядом с местом, где возникли.
**Минусы:** код дублируется во всех роутах, а в новом роуте про `try/catch` легко забыть.

### Выбор: четыре параметра

Одна точка обработки на всё приложение, дублирования нет. Функция должна иметь четыре параметра, даже если `next` не используется.

## Порядок регистрации

1. `express.json()`
2. роуты: `GET /cards`, `POST /cards`, `DELETE /cards/:id`
3. обработчик неизвестных адресов (404)
4. обработчик ошибок (500), самым последним
5. `app.listen`

Обработчик 404 стоит после роутов: если поставить его раньше, он ответит на все запросы и рабочие роуты не сработают. Обработчик ошибок стоит последним, потому что Express ищет его среди middleware, зарегистрированных после места, где произошла ошибка.

## Изменения в коде

Меняется только `server/index.ts`:
- добавить `app.delete("/cards/:id", ...)`;
- добавить обработчик 404;
- добавить обработчик ошибок.

Клиент (`client/`) не меняется: он уже отправляет `DELETE /api/cards/:id` и проверяет только успешность ответа.
